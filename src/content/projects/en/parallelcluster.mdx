## The situation

Research teams needed production HPC capacity on AWS for molecular
dynamics, atmospheric chemistry, genomics, and Python-based data science.
I designed and delivered a multi-user ParallelCluster v3 environment with
Slurm scheduling, shared scientific software, controlled access, and
project-level cost limits.

## Constraints

- The platform had to serve both multi-node MPI jobs and high-memory single-node workloads.
- Project spending needed enforceable monthly limits without manual policing.
- Access had to require IAM-gated MFA while keeping SSH off the public internet, and Linux users needed their own UID, GID, groups, and home directories.
- Compute options were constrained by availability in the cluster's us-east-1 region and the remaining lifespan of the AWS platform.

## Approach

I configured two Slurm queues: one with EFA for MPI workloads and another
with high-memory nodes for single-node jobs. Encrypted EFS provided shared
home directories, while a 4.8 TB persistent FSx for Lustre filesystem
provided high-performance storage and local NVMe SSDs served as scratch.
The software environment used Spack, Conda, Apptainer, and Lmod. I also
wrote user documentation covering onboarding and advanced use.

I implemented a scheduled budget daemon that read Slurm accounting data
and compared each project's month-to-date node-hours with its monthly
budget. Since AWS bills for nodes rather than cores, the daemon calculated
cost by queue. It blocked submissions when a project reached its limit,
restored access after a top-up, and reset budgets each month.

IAM Identity Center handled authentication and authorization. Users
connected over SSH through an SSM tunnel, with no public port 22. AWS
Simple AD mapped authenticated usernames to Linux identities and home
directories. I configured CloudTrail, VPC Flow Logs, AWS Config,
GuardDuty, Security Hub, Inspector, IAM Access Analyzer, cost guardrails,
an EC2 kill-switch SCP, and a dedicated OU with region, IMDSv2, and
instance-type service controls. I also migrated shared home storage from
unencrypted to encrypted EFS.

## Key decisions

I used Slurm accounting to enforce project budgets automatically. The
daemon priced node-hours by queue to match AWS billing, blocked submissions
at the monthly limit, and restored access after a top-up.

The lower-cost hpc6a and hpc7a instance types were unavailable in
us-east-1. The cheaper hpc7g option used ARM, which would have required
migrating the scientific software stack. Moving regions or building a
multi-region VPC would also have added substantial work. I chose eight
c7a.32xlarge nodes available in-region, accepting standard ENA networking
instead of EFA for MPI on this queue. That trade-off fit the users' needs
and avoided a larger change for a platform nearing end of life. The Azure
replacement was confirmed while configuration was underway, so the queue
did not enter full production.

I kept cluster access separate from Linux identity resolution. IAM Identity
Center and MFA controlled access to the cluster; Simple AD mapped usernames
to Linux identities. SSH over SSM kept port 22 private while retaining
command history, file transfer, X11, and port forwarding.

## Outcome

The AWS ParallelCluster platform restored production research computing
capacity with scheduled access, shared scientific software, user
documentation, and automatic project budget enforcement. It was later
decommissioned after being succeeded by
[the Azure CycleCloud platform](/projects/acc).
